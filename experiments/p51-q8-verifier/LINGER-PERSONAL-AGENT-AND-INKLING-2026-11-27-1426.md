## Why Linger fits, and what it cannot solve

It could be the persistent personal-agent front door, a cross-computer or multi-agent orchestration layer and a source-linked knowledge base around our QFN/27B/Mini workers. It is not a replacement for QFN runtime, the canonical Git repository, exact-prefix reuse, or CUDA-to-Metal transfer. Do not confuse three persistence levels:

1. **Application state**: shared wiki pages, room/task membership, task progress, documents, explicit milestones, source-linked memory, computer identities, UI. Service uses PostgreSQL17/River + Node, Yjs collaboration. A computer daemon connects outbound via WebSocket; per-context workspace; local SQLite event ledger persists before send and replays following reconnect. Teams use team.md handoffs. Meta/AlterEgo tasks have separate native sessions, resumable after cancellation, files retained; independent rooms and tasks, not a distributed model.
2. **Agent runtime state**: Pi/Codex/Claude native session and compaction; local model uses Pi only. Idle compaction gate .65.0 Pi/.66.0 Antigravity. Recovery requires exact tool schema, request completion and history retention checks. Saved transcript does not imply numerical state continuity.
3. **Inference state**: model hash, quant, KV, GDN, PLE, loops, positional metadata, sampler, draft, prefix identity, cache format. No inspected evidence Linger transfers these across engines or resumes exact raw attention/recurrent cache on restart. Keep a separate persistent cache at the chosen engine, check actual cached-prefix and true cold TTFT. Relay remains independent research.

## Memory system strengths and failure modes

[Wiki memory](https://github.com/simplexai-labs/linger/blob/936e404fc0299782ff9592f422d1a9639606246b/docs/wiki-and-memory.md), [memory benchmark](https://github.com/simplexai-labs/linger/blob/936e404fc0299782ff9592f422d1a9639606246b/apps/node-services/scripts/memory-benchmark/README.md). Room memory is extracted after5 successful runs, consolidated after6h idle or compaction; scope room, not necessarily task/doc work. A context digest is inserted as an ordinary hidden message, not a system prompt. Structured wiki pages have bounded summaries (~3000 chars), list caps20 items×500, changelog20, citations to original messages. Keyword PostgreSQL FTS, alternate phrases, temporal rank not hard filter, no vector retrieval requirement. Benefits: project preferences, prior decisions, people, recurring notes, linked material and cross-worker handoffs. Limitations: delayed extraction, truncation/compression, stale/conflicting facts, missing recall due to keywords, prompt injection/poisoning from untrusted sources, false memories, hidden context extra tokens and loss of cache reuse. Keep Git as authority for Project51 constraints; every consequential memory must point back to source and explicit correction/version, no self-modification of floor/frozen experiment. 
The repository has a pinned LoCoMo/LongMemEval-S benchmark design and synthetic 11-question two-day memory lifecycle fixture; no public actual comparative scores found. Fixture does not test scheduler/runtime and admits occasional recall misses. This is promising testing infrastructure, not proven long-horizon reliability or clinical/personal recall accuracy.

## Proposed experiment ladder: use case / pass gates (never auto run)

Phase 0 – read license/security and platform approval, select isolated non-admin test account, throwaway git repo, no secrets, no signed-in browser, no work files, no external service credentials, localhost/private authenticated LAN only, restrict outbound. Pin one runtime, model and tokenizer SHA, quant, sampler/temp, actual context size, cache reset rule, tool parser version, no draft baseline. Keep Linger service and engine logs, event IDs and hashes, error budget, memory and VRAM. No automatic fallback.

Phase 1 – compare native Pi/bare baseline vs Linger same engine/model, prompt, sampling, same context (8/32K then 90/128K only if fits), 20-turn memory task + 1–2h coding run. Tool fixture >=20–30 known operations: typed booleans, numbers, nulls, nested arrays, escaping, assistant tool ordering, EOS/length/stop, malformed chunks, late reasoning, duplicate call IDs, stream timeouts, no explanatory text substituted for tool; fail closed and no unintended effects. Use known one-slot concurrency, measure counts and max simultaneous requests, cold PP, warm PP, TTFT, output TG, actual occupied context, tool latency, total task wall, RSS, peak VRAM, pressure, SSD writes, native cache hits. Include quality and test suite results, not token agreement alone. Strata #7321 finish status bug and Basalt #629 typed boolean issue are concrete compatibility gates.

Phase 2 – behind isolation, crash daemon then server then engine separately mid-task (only controlled test), reconnect, verify replay once, state/room/source IDs, test files/commit hash unchanged except authorized changes, no duplicate side effects. Distinguish application/native restored session vs warmed raw engine cache. Cancel then resume; background memory while busy; force interleaved conflicting facts, correct one, verify source link and stale fact rejection after compaction; task and room transfer. Check whether task worker DB failures generate bounded retries and clear progress after restore.

Phase 3 – two Macs independently (plus main PC if memory safe), hand off code review in separate worktrees and team.md; prevent concurrent same-file edits, pin branch expected parent, verify source citations and final tests. Compare tasks/hour and time to solution with one worker, two separate native workers, and Linger. Expose no external connector writes. If Linger memory silently truncates constraints or auto-changes quant, hold adoption. Do not modify P69B12/B13 or Relay validation gates.

Phase 4 – optional Mini adaptation (distinct from inference). Native QLoRA/PEFT small synthetic task and held-out evaluation before any company data; [Unsloth #19991](https://github.com/unslothai/unsloth/pull/19991) on-load low precision LoRA can reduce peak memory but not Mini-specific, [#20007](https://github.com/unslothai/unsloth/pull/20007) Mini full training reported 96GB run and ~97.8GiB weights+grad before optimizer; in-backward requires GA1 no distribution, fallback changes optimizer. No free-tier ThunderCompute or Colab Pro VRAM guarantee. Test adapters against native baseline, long tasks, quantize only after held-out validation; retain base and separate revision. No actual fine-tune authorized.
