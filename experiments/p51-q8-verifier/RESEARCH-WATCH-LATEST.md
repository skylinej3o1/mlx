Existing loader `validate_split` rejects hardlink same PLE across split.count=2/3/4. Patch relaxes metadata validation ONLY if a shard consists exactly of single `per_layer_token_embd.weight`, retains main shard checks. `iq_pack.py --compat-bf16` with cross-split hardlink passes, and live Strata0.2.11 generation on ONE configuration reported. **Practical**: one 28.8GB shared lookup-table shard means ~28.8GB DISK/transfer saving per extra source/unloth quant held locally; not 28.8GB less model's intrinsic per-agent KV or automatic full unified RAM saving, and split adapters elsewhere must support it.
