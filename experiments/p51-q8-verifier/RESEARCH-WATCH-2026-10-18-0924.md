## 1. RECOVERED OLDER, USER-PROVIDED PAPER — Terminal-RSI on exact target Qwen3.8-27B

**Primary:** https://arxiv.org/html/2610.22192v1 ; submitted **Oct 15 2026**, version 1. **Authors' landing:** https://jyyang26.github.io/terminal-rsi/ shows **"Code soon" and "Model soon"** as checked on Oct18; no deployable author checkpoint or training reproduction available yet. This is a **27B actor post-training paper**, NOT a quantization/kernel/drafting improvement and not a Flash-Next MoE checkpoint.

**Method and contribution in the paper's own terms:**
- Five-stage retained policy path: **Base Qwen3.8-27B → Recursive Self-Rewrite (RSR-1) → Recursive Policy-Refine (RPR-1) → RSR-2 → RPR-2** final `Terminal-RSI-27B`. RSR learns from *freshly verified* runbook-guided replay of successes under a target harness, reviews leakage, strips private guidance and retains actor-only training. RPR combines policy optimization with an **inherited critic**. One initial frozen-actor SWR epoch prepares warm-up critic, four critic-only updates recalibrate values at each RPR phase before joint optimization. In RPR-2 actor LR decreases 5x **5e-7→1e-7** while critic remains **1.5e-5**.
- **Turn-Boundary Skip-Observation GAE (TB-GAE)** discounts credit across consequential agent turns rather than arbitrary observation-token verbosity; within-turn kept-token value baselines remain prefix specific. **Important nuance:** appendix and method say the **documented first RPR phase used ordinary gamma=lambda=1 GAE**, so one must *not attribute the observed stage gain to a controlled, deployed TB-GAE ablation*. Fully exact cross-chunk continuation must carry **both next-boundary value AND next-boundary advantage** (or run a full reverse scan); resetting trace is not equivalent. Summarization changes conditioning and is not lossless KV compression.
- **Family Dense Reward (FDR)** scales semantic passed-check counts per task family; **Success-Prioritized Reward (SPR)** explicitly gives strict completed success priority plus bounded partial progress. Under FDR authors audited 4,352 trajectories: failed episodes held **50.09% of total reward mass** and 48 failures passed every executed scenario check while missing the terminal gate. On identical trajectories SPR rescoring cut failed reward allocation to **28.72%**, *not* proof isolated online training effects.
- 3,000 training tasks =2,400 semantic-verifier plus600 supplementary. Infrastructure slime/Megatron/SGLang/Harbor, asynchronous PPO rollouts with context parallelism4, global batch256, no typical single-M1 or single5070-sized training recipe. Retained posttraining on source 27B, not evidence of quick user local fine-tune.
- **Evaluation: 262,144 model context capacity but only 96,000 INPUT tokens/request**; proactive **summarization at 32,000 accumulated**. Each turn up to8192 output tokens; temp0.60 top_p0.95, explicit thinking disabled, structured JSON actions, raw linear history, up to100K turns subject to actual task limits. Three **inference repeats (Mean@3), NOT 3 trained seeds**, four-suite equal-weight mean, not an average of SWR/LHTB or combined all tasks. It **does not demonstrate a 262K native-context coding-agent turn, nor dense27B model-download availability**.
- **Stage scores** — [TB4 / TB2.1 / TB3 / TB Hard] (%) Base **0 / 51.70 / 0 /31.00**; RSR1 **6.10 /70.10 /6.80 /54.00**; RPR1 **16.67/77.53/14.29/69.50**; RSR2 **17.46/86.52/15.00/76.00**; final **19.84/86.52/16.95/79.00**. Four-suite equal-weight mean **20.68→34.25→44.50→48.75→50.58**, +29.90pp base→final.
- **Hard limits:** LHTB dense process0.21→0.37 but **only 5/46 strict task completions** final; SWR1003%→6%, unchanged in final 3 training stages; extreme difficulty subset final10.98% and nonmonotonic. Paper explicitly says no compute-matched, isolated TB-GAE/reward/critic controls and no independent training seeds; different training schedules/selection are confounds; 27B model's checkpoint not public. Author-provided frontier comparison (e.g. GPT-6 Sol TB2.1 85.4 vs model86.52) is **not same-harness independent evaluation**; do not frame as proved beating any frontier model.
- **Project51 impact:** promote evaluation/training *methodology*: terminal-verifier strict S as top KPI, calibrated partial-credit diagnostic not objective to game; protect runbook leak filtering, replay test task in fresh clean environment/harness, attributable error taxonomy (wrong tool ID, early `</think>`, lost prefix, wrong KV). Measure **verified tasks completed/hour**, retries, prefill from0, and multiagent restoration (3–5 concurrent sessions) with task-family strata; use paper's success-vs-progress gap as reason not to optimize TG in isolation. RSR-inspired playbooks and protected execution possible *without RL*, but **do not claim equivalent trained-model capability**. Watch code/weights; only when actually released, checksum checkpoint, model architecture, license and eval behavior before an M1 oQ4e vs original Qwen3.8-27B same agent gate.
